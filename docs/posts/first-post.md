这是我个人博客的第一篇文章。写下来有两个原因：**一是给自己一个沉淀的地方，二是给未来的审读者一个能查证的入口。**

## 为什么要写

读研之后我意识到，学过和学会之间的距离是"能不能把它讲清楚"。看论文、读源码、调 bug 的过程如果不落到文字上，三个月后基本等于没做过。

还有一个更实际的考虑：简历上一行"熟悉 Spring Boot"是没有说服力的，但如果附上一个链接，里面写清楚了你在什么场景下做了什么取舍、为什么这么做，信息密度完全不同。

## 选型过程

我的需求很明确：

1. **零成本** —— 不想为一个还在起步的博客付服务器费用
2. **零运维** —— 更想把时间花在写内容上，而不是配 Nginx 和续 SSL 证书
3. **写作体验好** —— Markdown 优先，公式、代码、图表都要好看
4. **可长期持有** —— 不能依赖某个说关就关的平台

基于这几点，最后选了 **VitePress + GitHub + Cloudflare Pages**：

| 环节 | 方案 | 成本 |
| --- | --- | --- |
| 内容 | Markdown 源文件，Git 版本管理 | 0 |
| 构建 | VitePress 静态生成 | 0 |
| 托管 | Cloudflare Pages，全球 CDN | 0 |
| 证书 | 自动签发并续期 HTTPS | 0 |
| CI | push 即触发构建部署 | 0 |

整个链路没有一个需要我手动运维的环节。写完 `git push`，两分钟后文章就上线了。

## 关于写作工具

Markdown 的好处是工具无关。我习惯在本地用编辑器打开整个仓库写，`docs/posts/` 下一篇文章一个文件，图片放在 `docs/public/` 下按文章分目录。

如果你想用 Obsidian 管理，可以把它的 Vault 直接指向 `docs/posts/`，写完之后回到命令行 `git push` 就行。
